# 原文版本、逻辑定位与失效

读者：解析器、运行恢复、Workbench 和索引维护者。修改触发：分段算法、源修订、依赖身份、迁移或缓存协议改变。当前任务进度仍由 `governance/round_state.yaml` 的 `codex_governance` 管理，本页不授予真实资料迁移或正式稿切换权限。

解析器保留 `ch-N-seg-M` 作为旧接口 ID，同时给每段附加 `segment-source-binding/1`：完整 UTF-8 文档 SHA256、码点半开范围、段内容 SHA256、逻辑 ID、重复出现次数与绑定摘要。逻辑 ID 由章、段内容和重复序号派生，唯一未改段插入前文后仍可定位；它不能证明旧译、审核或缓存有效。重复段落明确为待核对，不能依靠相同文字猜迁移关系。

范围指向原始解码文本，保留 CRLF、Unicode 和标题前后的真实位置。解析器继续沿用原有分段规则，标题不进入译文段，行结束符转 LF、段外空白移除的变换有显式标识。创建时用完整原文重建验证范围；仅拿到摘要的下游校验能证明元数据自洽，不能独立证明对应文件存在或内容可信。

`segments.json` 保留章修订、解析器版本及每段绑定。draft 请求带当前绑定，run identity 固定全部源文件、绑定和解析器版本，邻文目录身份也包含这些版本。因此仅改标题、等长改字、插段、合句或拆句都不能静默恢复旧检查点。源与配置未变时仍可恢复，不额外调用 provider。旧检查点没有这些身份字段时保留原文件并拒绝自动升级，不能补一个 PASS 后复用。

现代 Workbench 审查身份绑定源范围摘要与可选依赖摘要。既有清单在保存或重新导入时，若有序来源范围改变，就在原清单内记录 `source_context_revision`；读取时从清单派生到段，用户请求不能通过省略段上的元数据退回旧身份。改变其他段落，也会使当前段旧决定失效。目标文字变化仍单独改变审查身份；目标变更不伪装成源修订。未变的旧数据继续可读，旧状态和决定记录不被改写；现代来源范围一旦建立，恢复旧文字也不恢复旧 v1 审查。UI 必须使用当前 Workbench payload 中的 approval_identity 发起 CAS，不能在脱离当前来源范围时自行计算旧身份。

`propose_source_migration` 只在内存中提出旧 ID 到新 ID 的定位，保留旧/新版本与双方范围。未变的唯一文字可形成对应；最多四段的连续合句/拆句可以形成位置候选。去空白匹配、重复内容、章不一致或无法定位均不能证明语义对齐。所有结果的 apply_allowed、target_reuse、approval_reuse 均为 false；没有本次依赖核验的迁移执行器，不复制旧译或批准，也不改真实资料。不可定位项留在原分母。

段索引 v2 的文件指纹与内容摘要使用完整内容 SHA256，不再使用大小加整秒 mtime，也不以段长代替内容。指纹和扫描从同一字节快照产生，旧 v1 缓存不自动复用。输出只保存摘要和范围，不保存原文/译文正文。人物和术语用例索引也固定源文件内容、术语输入和算法依赖，源不变但术语版本改变会重新扫描；未改输入可复用。

本轮只在隔离合成副本上验证解析、索引、清单和恢复。CN_TO_JP 可使用相同源定位元数据、方向隔离身份和结构化导出接口；这不证明反向翻译的实际文学质量。真实资料中的旧对齐与知识/TM 血缘仍按 P3 单独核验，不因本接口存在而被自动解封或采用。正式 canonical、导出与 UI 闭环属于后续任务；当前修订不能替代这些验收。

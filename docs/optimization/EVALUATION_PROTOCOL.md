# 源文质量评价协议 v1

协议身份：`source-review/1`。读者为开发集评价、P2 候选修订与 P5 冻结回归的实施者和独立审查者。修改触发为输入血缘、错误分类、严重度、接受条件或统计方法变化；改变后保留旧协议与曝光身份，重新校准受影响部分。任务状态及下一步只查 `governance/round_state.yaml` 的当前 `codex_governance`，本页不调度任务。

## 输入与证据

真实开发数据只通过固定 SHA256 的 `DevelopmentReader` 放行。原文锚点包含方向、章节、完整原文版本和 codepoint span；上下文保留自身范围与原文版本。旧译由登记的 record_id、容器版本、字段及指针推导血缘，不能由调用者自报“开发章”。旧 approved、locked、人改标签均不构成可靠参考。保留集目标、裁决与反馈继续封存。

盲包 `source-blind-evaluation/1` 固定源文片段、先前源文上下文、两个匿名候选及各自哈希。上下文、片段、候选和其他案例字段一起进入 canonical JSON 的完整案例指纹；作者控制标签固定该指纹。评审必须回传实际输入完整包的指纹，不接受只绑定其中引用子串的旧评审。第二包只交换 A/B 和目标版本，其他案例字段必须完全相同。血缘单独保存在私有证据中，避免向评价者暴露哪个候选来自旧译。

`source-calibration-view/1` 分开源文优先的选择、文学偏好、严重错误否决和逐项问题。问题至少有源/译文定位、类型、严重度、置信度和理由。`validate_view` 验证身份、结构和引用位置；它不能证明语义判断正确，也不是接受或批准服务。未知字段不能引入人审/最终批准身份。结果固定 `agent_proxy / not_granted / auto_acceptance_enabled=false`。

位置采用 Unicode codepoint 的左闭右开区间，片段内位置通过已登记的原文 span 映射到完整章节。普通引用必须唯一；重复文本允许显式 span，但必须与引用逐字匹配。遗漏不能伪造一段不存在的译文作为引用：可引用可核对的相邻译文，或用 `OMISSION + omission_gap`、空 target_quote 和显式 `[n,n]` 表示缺失位置。缺失含义仍须源文证据与语义审核，零宽位置本身不能证明遗漏。

## 六维结论与严重度

沿主计划 §6 分开工程完整性、忠实度、长文一致性、文学表达、个人偏好、资源。错误类型可描述误译、遗漏、增译/重复、错语言、指代/说话人、时序/模态、称谓及信息揭示；不把人物名字或某作品规则写入核心。

- `critical`：任务没有完成目标语言翻译，或关键行动、关系、信息揭示遭到根本性破坏。
- `high`：有源文依据的事实、主体、主宾、否定、条件/时序、可能性等被改变；删除完整命题或无依据重复完整句子的控制反例列入此层校准。
- `medium`：局部语义/语用或表达问题，尚未证明达到上述事实性损害；严重度存在争议时保留两份原判与证据，进入待核验。
- `low`：不改变原义的局部表达建议。合法合句、拆句、重排、语境多译、保留未知主语和人物语气差异本身不是错误。

文学/偏好只报告有理由的胜、平、负或无法判断，不规定必须产生赢家。文学上更喜欢某候选，不能覆盖其 high/critical 源文冲突。置信度是评价者声明，不能视为已校准概率或阈值。未知人物关系、未来事实和不完整上下文不得靠补故事解决。

## 冻结的接受条件

工程硬条件沿既有已测实现：源清单覆盖、合法 ID/span、数据/Prompt/知识版本匹配、失败不进入成功、模拟不污染真实、零授权预算不调用、可恢复。工程通过不能证明译文正确。

本版**不开放语义、文学或个人偏好的自动接受**。`summarize_source` 始终返回 `auto_acceptance_enabled=false`、`human_approval=false` 和 `default_action=preserve_original`；没有代码路径从控制统计授予 canonical 或人审身份。机器零问题、两个 Agent 同意、1.0 置信度、较高文采均不能解除此条件。

共享领域服务 `canonical_service.prepare_revision_comparison` / `apply_revision_comparison` 现在提供单段比较与明确选择后的**待复审草稿导入**。旧稿从当前项目读取；原文版本、完整源清单、精确 spans、最多 512 codepoint 的前文、选中依赖及该段审核记录共同绑定私有计划。应用时重新核对上述绑定、交换视角和明确选择的目标原始哈希，并拒绝活动生成任务。缺失证据、平局、弃权、严重问题否决、归一化变体未全评或旧稿获胜时不写入；字节相同的共同胜者可以选择其文本，不据此认定某种方法占优。

本地 Agent/PSH 调用者仅被记录为草稿选择者，来源与评价仍是未认证声明，服务不签发通过审核的身份。成功导入只改选中段落，保留其他原始段落和有效审核；变化段落的旧审核自然失效，整项目既有选定版本及完整生成来源标签失效。旧 manifest 按原字节归档；私有变更记录保留差异、计划/视角指纹、选择者和完整源单元的累计预算快照。此步骤不运行模型、不消耗或重置预算；预算尚未登记时用未知表示，不能据此追认生成合规。新稿仍须现有独立审核 CAS 及明确版本选择，才能经过正式导出校验。

原生入口 `native_agent.execute_job(action="compare_revision", segment_id=...)` 已接入同一生成任务状态、项目/仓库锁与取消机制；本机同源 `native-agent-job` HTTP 请求仅增加选中段 ID，不接受候选、模型、回执或批准身份。当前薄路径要求精确、连续的单段源文 span；多 span 重分段仍须后续适配，不能把拒绝当成覆盖完成。任务先读取当前源文、旧稿、最多 512 codepoint 前文及选中依赖版本；若 manifest 明确选择 `work_rules={path,sha256}`，仅通过现有工作规则加载器核验其作品/源文/方向和 `review_only` 版本，不授予这些规则改写原义的权限。缺失依赖、过期规则或输入/审核变化在调用前后均拒绝。

一次任务依次完成问题诊断、至多一次简单修订和一次问题驱动修订、两个独立临时历史的匿名交换比较。无可定位问题就停止；不强求不同候选或赢家。每次回调先经过既有完整源文 `operation` 与 `physical_attempt` 持久预留，沿用累计 8 次操作、2 次修订、1,200 秒源文时钟；不自动重试，不因新 request ID 重开相同输入。提取器仅验证结构和覆盖，方法血缘保存生成回执中的原始目标文本，归一化等同不等于原始字节相同。

私有任务目录保存问题、方法计划、原始候选、交换视角及各次原生 prompt/answer/receipt 的哈希绑定；公共响应只有任务状态、固定原因、候选身份和验证范围。`native_revision.completed` 从成功终态任务重验所有文件、原生回执、独立临时历史、对应源单元成功扣记及当前源文/旧稿/审核/依赖。`native_revision.apply_completed` 只供受信本地 Agent/PSH 以明确目标哈希另行选择，且复用上述待复审草稿服务，不开放 HTTP 批准入口。回执绑定证明的是这些输出和调用的对应关系，不认证评价的语义真伪。UI 入口、真实原生修订采用及真实比较收益尚未验证；隔离合成样例通过不代表 T01、文学质量或全范围完成。

匿名修订比较的 `experimental_winner` 与 `default_action` 分开表达结论和安全动作。证据缺失、输入无效、弃权、平局、两视角分歧、未闭合语义问题或循环比较时，胜者为 `null`，动作仍为 `preserve_original`；严格逐文本入口遇到重复候选会终止该三候选路线。不能把保留旧稿记成旧稿获胜。只有完整有效的配对图和交换视角一致支持唯一安全胜者时，才返回该候选身份，包括有证据获胜的 `B_old`。两候选结果保留 `old_vs_simple_partial` 或 `old_vs_problem_partial` 范围，不能冒充三候选比较。`complete=true` 不等于存在胜者，也不授予接受、canonical 或人审身份。

`plan_method_comparison` 另行规划三种方法条件与不同文本之间的关系，不改变严格入口的重复保护。调用者必须提供绑定原始目标哈希的三份来源记录；它们只作为未核验的来源声明保存。字节相同的输出共享一个实际文本代表，原来的方法身份和哈希全部保留；代表选择只用于序列化，不表示方法优先。三份不同文本形成三对，只有两份不同文本时形成一对，并标为 `two_unique_targets_partial`；全部归一化等同时为 `identity_only`，不调用评价器、不选胜者。相同文本不能证明某种方法更好，不能为凑出第三份措辞追加生成。

评价器只接收 `method_evaluation_packets` 导出的源文、上下文及匿名 A/B 包；来源、等价组、条件映射和原绑定字段留在私有计划中。导出前和聚合前都重算完整计划，拒绝篡改、过期来源和不一致的配对。`aggregate_method_comparison` 将已评估的字节相同胜者列为共同条件；若胜出文本属于多个方法条件，主字段 `experimental_winner` 保持 `null`，`experimental_winner_target_revision` 记录胜出文本的原始哈希，`byte_identical_winner_conditions` 同时列出这些条件，原因标为 `equivalent_conditions_share_winning_target`。仅当胜出文本只属于一个条件时，才报告该条件为实验胜者。`representative_experimental_winner` 与 `representative_reason` 仅作代表文本的诊断记录，不能作为单个方法胜出或方法优势的证明。仅 NFC、换行或首尾空白归一化后等同的原始变体仍保留各自哈希，不能将代表文本的判断推广给它们，整体胜者保持 `null`。所有归一化变体、身份核验和代理批准仍需要各自适用的后续证据；本接口不签发接受、人工审核或正式稿身份。

后续受控 Agent 代理决定须绑定确切源文、上下文、知识及候选 revision，并至少有一名未参与改写的源文审阅者。high/critical、未闭合的遗漏/增译、严重度分歧、未知来源或关键指代不明时保留原稿和 pending；不能因某评价者只判 medium 就绕过已知冲突。文学偏好仅在忠实度和完整性没有未决关键问题时比较。自动接受若要启用，须在开发集预先冻结适用风险簇、可验证误报/漏报界限和不退化条件，以独立证据证明关键退化可识别；本次小样本不足以制定通用数值阈值。此限制只禁用未校准的自动改写，不把普通争议转给用户逐段审批；用户保留最终校准。

## 统计与原始分母

作者的合成/开发控制预期标为 provisional，不能称为人工金标或旧译真值。每个候选标 `severe / not_severe / unknown`。unknown 仍在原始分母，不计入 TN；已知正例上的 abstain 进入 unknown_prediction_positive，recall 的分母仍包含该正例。

分开统计：

1. 任意源文问题是否被发现，及相对于控制标签的 TP/FP/TN/FN。
2. high/critical 否决是否触发；发现遗漏却只给 medium，计入发现成功和严重否决漏检两个不同结论。
3. 各风险/控制类别的原始计数、precision、recall、未知参考和未知预测。无分母的指标为 null。
4. A/B 交换后的源文优先选择与文学偏好分别归一化，保留不一致案例、候选长度和原始理由。作者原本认为两译等价而评价者更偏爱其中一译，不据此改标签或宣称语义优越。

同模型两份独立历史的能力并非强独立。当前两份历史与展示顺序同时变化，只能给出顺序归一后的诊断一致性，不能把差异归因为顺序偏差或估计模型总体偏差。按章节/叙事区段报告，不能把相邻候选/句子当独立大量样本。当前每类仅一两个控制，拒绝伪精确的总体区间或显著性；给出每类分母及样本限制，后续扩大后再按冻结的区段抽样计算区间。

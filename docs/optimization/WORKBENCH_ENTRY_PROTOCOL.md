# Workbench 实际入口与版本证据

## Round60 完整区段的共同入口

`canonical_workbench.py` 的 `source-import`、`native-job --action generate|review`、`restore-previous`、`select-version`、`export-selected` 与 `status` 直接复用 Workbench 的领域服务。根目录和项目必须显式指定；原生任务必须提供当前 manifest 摘要、唯一请求 ID 及 `--confirm-native`，选择和导出分别要求 `--confirm-select`、`--confirm-replace`。CLI 不接收模型、审核者或批准身份参数，也不输出源文、译文、审核正文及私有原生线程 ID。重复、过期、未获接受和失败请求沿用服务端的保留与拒绝规则。

完整真实开发区段试验只在预先登记的私有根下执行；正文释放、原生准入和模型操作仍须绑定本轮确切候选的独立预审及 Governor 批准。正式工作区、scheduler 和原件不随私有试验改变。试验的实际接受或拒绝、预算、恢复、撤销、语义审查及导出证据只能查唯一 State 与对应本地回执；本协议不预先授予任务、质量或整体验收。

## Round59 上一份候选恢复

审核页提供“恢复上一份候选”，确认后只恢复与当前源清单、逐段源定位和审核依赖完全一致的上一份快照中的候选文本。当前原始 manifest 先按内容摘要归档，再原子替换；再次恢复可撤销这一步。空候选也可恢复。变动段落为待审核的新恢复版本，旧接受意见不会因文本相同而复活；未变段落和现有审核文件保留。恢复不运行模型，不重置源单元预算/时钟，也不切换正式稿。

CLI 复用同一服务，根目录与项目必须显式给出：`python scripts/canonical_workbench.py --root /absolute/project --project PROJECT status`；恢复使用 `restore-previous --expected-manifest-sha256 CURRENT_SHA --confirm-restore`。输出只有版本、计数与状态，不输出源文/译文。HTTP 只接受本机同源 JSON 的当前摘要及显式确认，不接受快照路径、审核者、模型或身份字段。过期版本、运行中作业、锁冲突、源文/依赖变化和不可信快照均保留当前候选。

此入口工程验证限于隔离合成数据及私有无头浏览器。完整开发章节的 CLI/Workbench 实际闭环、正式导出和采用仍属于 P2.R04.T02 后续验收，不能由此段文字推定完成。

P2.R03.T02 的本轮候选沿现有静态 HTML/JS、深色 tokens 和中文交互实现。沿用 `docs/design/DESIGN.md`；未创建新设计文件，未调用 Stitch、Figma 或改变其配置。当前浏览器工具存在，但本轮需要独立 PID、网络、文件和浏览器配置边界，因此由项目 Playwright 运行器在既有合成 namespace 中操作真实安装的 Chrome。原文、旧译、私人风格和实际正式稿未进入测试视图。

## 用户路径

首页“导入长篇原文”读取用户选择的全部 UTF-8 章节文件，严格解码且保留 BOM，不按小样本段数裁剪。按文件名明确排序，方向决定 input_jp/input_cn；每个新项目保存源字节、完整文档 SHA、parser spans/binding 和独立冻结源清单。空章、重复文件/章节标识、路径不安全或既有不同内容均拒绝，不覆盖现有项目。请求上限 32MiB；更大输入的分批导入和全书吞吐不是本轮验证范围。

审核页和导出页显示完整源范围、候选覆盖、当前 Agent/PSH 接受数量和显式版本选择。详细身份放在“版本与恢复信息”，避免把哈希当作普通用户需要手填的参数。Agent 输入下载包含完整源段和冻结清单身份；下载不会运行模型、消费生成额度或证明某个模型结果。已验收的长篇路径是下载受控 Agent 任务输入并导入绑定候选；下文原生执行桥仍是待准入候选，未增加后台调度器。外部 API 按原有 opt-in/成本护栏走短样例，最多 3 段/每段 400 字；超量显式拒绝，不再静默取前三段。实际受控生成/收益、候选接受领域服务和生产运行仍按 P2.R04/P5 验收。

候选 JSON 只能包含清单身份以及按源顺序完整覆盖的 segment_id/target_text。新候选保持 imported/unreviewed；不能在 JSON 或 HTTP 中提供 Agent/人审资格。写入需要当前 manifest SHA，源身份错误、缺段/重复/空译文或活动生成作业均拒绝；写前保留现有 manifest 的不可变内容版本于同一 manifests 下的 .versions 恢复目录，当前权威仍只有项目 manifest。

“记录通过意见”是身份未知的本地意见，显示中性徽章，不能解锁正式导出；机器建议也不升级。既有可信本机 Agent/PSH CAS 的当前决定才计入接受数量。点击“选择已获接受的当前版本”仅捕获已有决定并显式选择 draft 字段，复用 T01 build_accepted_revision，绝不签发新审核身份或用户最终批准。拒绝/修改使接受失效，项目切换同步版本面板，过期请求不能覆盖较新的面板。

正式导出先选版本、再独立确认切换当前方向唯一正式稿，调用共享 T01 校验/不可变 bundle/指针发布路径。完整源文、当前接受和输入/审查版本在提交前重核，异常保留旧稿。辅助预览仍写 workspace/workbench_exports，页面明确标为非正式稿；不再误称 output_cn 正式交付。旧快照保留，显式候选恢复/撤销工作归 P2.R04；当前失败恢复为刷新版本后核对并重新选择，不隐式重试。

## 证据与边界

隔离入口：`.venv/bin/python scripts/isolated_checks.py --entry ui ...`，内部实际执行 `npm run test:ui -- --workers=1 --retries=0 ...`。只复制已登记工程/合成文件，复用只读 node_modules、Node、安装的 Chrome、.venv；原 home/data/运行状态不可见，清空凭据环境并隔离网络和 PID。服务绑定独立 namespace 中 5174，禁止复用未知服务/浏览器配置。正常结束验证 npm 退出、fixture 端口关闭及临时视图移除。无头浏览器没有物理显示连接；Xvfb 在 namespace 中的 Mesa 崩溃保留为环境失败，没有禁用 GLX、解除隔离或改用前台。真实 headed/X11 路径仍未验证。

实际 Playwright 路径覆盖 1280×900 和 390×844，完整 2 章/7 段导入、任务下载、候选上传、未知通过意见不授予接受、原生合成夹具建立接受、UI 拒绝与失效、重新建立本机合成接受后显式选版本、确认导出、过期导出 409 保留旧 bundle，以及项目切换。原生接受夹具直接调用已有 CAS，仅是测试前置，不是 HTTP actor override、文学评估或真实模型审核证据。console/pageerror、网络交换和截图分别保存；桌面/移动端、键盘焦点、减少动效、错误/禁用/确认均有相应覆盖。4 个既有跳过测试保留原因，不计为本轮通过；旧测试把匿名意见当正式接受的假设按当前领域合同修正，不放宽后端资格。

页面基线保留移动端导出页横向溢出失败，新候选复测修复。关键 UI 完整性与文学质量/全书规模/实际 Agent 运行分开报告。T02 的完整验收仍要求实际原生 Agent 执行和独立审查；下载文件或合成接受夹具不证明该桥已接通。

## 原生执行桥候选（尚未通过实际准入）

审核页新增“用本机 Agent 生成完整候选”和“独立 Agent 审查当前候选”。固定的本机同源 JSON POST 只收项目、当前 manifest、动作和请求 ID；HTTP 不能提供命令、模型、Prompt、环境、额度、actor 或批准字段。跨源、额外字段及无完整源版本均拒绝。当前模块是本地候选；最新准入与实际采用只查唯一状态，不以按钮存在声明可用。

共享 `generation_jobs` 保存运行/失败和幂等结果；同 ID 的失败不会自动重放。原生准入失败另存现有 ControlledRun 检查点，配置/CLI/适配器身份未改变时，新请求 ID 或服务重启也不能重新启动准入。状态查询只读原子快照。跨进程原有 checkpoint 文件锁限制同仓库原生操作串行，完整源文件通过 `SourceBindings` 绑定，沿用源文版本的 8 次可观测操作、2 次修订及 1,200 秒累计限制。一次手动请求最多 10 个完整源单元、1MiB Prompt；超量明确拒绝，不截断长篇。已有候选不会由“生成”覆盖；修订与完整长篇分批仍属于后续闭环工作。

固定 `/usr/local/bin/codex` 只使用已登录 ChatGPT 的本机存储，保留配置默认模型，不读取配置/凭据原文、不接收 API Key，不传模型/profile/旁路参数。支持性检查使用当前 CLI feature/MCP 视图及 app-server config/read；关闭 shell、应用、Hook、子 Agent、插件、浏览器、图片和搜索，保持只读与拒绝审批。配置不被支持、工具无法确认关闭、登录缺失或模型探针未完成时，不发送正文。支持性检查通过后还须完成持久预留的零正文模型探针；它消耗 Agent 额度，隐藏重试仍未知。

生成输出必须按顺序完整覆盖当前段落，不能携带审核身份。独立的 ephemeral 原生审阅返回逐段裁决、置信度、严重度、原/译文引用及理由；引用不属于当前文本、覆盖错误、身份与生成者相同或输入过期均不能接受。低置信、严重问题及拒绝不会解锁导出。同模型多角色独立性有限。可信本机代码才调用既有 Agent CAS；CAS 校验冻结候选，并拒绝覆盖审查期间发生的用户意见。用户最终批准始终为 false。候选实现每次在同一个 app-server 生命周期内重新核对有效配置、登录与 provider，再从 thread/start 记录实际模型、provider、线程与进程身份；没有实际原生回执时仍不能声称完成身份验证。

前轮两次零正文配置准入失败，未运行模型探针、生成或真实审阅。首次仅得提前退出的通用错误；第二次在 strict feature 配置验证阶段拒绝。原始错误详情缺失，不能推断确定根因；脱敏诊断已补入代码，该轮已停止入口；后续诊断次数与结果只查唯一状态及当前合同。工程测试中的正向调用是显式注入的合成运行器；真实私有浏览器验证的是准入失败 503、伪造字段 400、跨源 403 和旧源/候选/审核保留，不能当作原生通过证据。

线程或轮次标识不匹配仍立即拒绝，保留原有事件消费与成功路径。错误诊断的 `protocol_event` 只包含有限的公开事件方法枚举（其他方法统一为 `other`），以及 `thread_id_state`、`turn_id_state` 的 `missing/null/invalid/match/mismatch` 状态。各错误、阶段和观察器边界重新校验类型与枚举，不保留标识原值、哈希、正文、原始事件或异常关联。该信息用于区分未来失败形态，不能还原此前已丢弃的事件或证明实际根因；合成测试也不证明实际原生运行已采用新诊断。官方协议事件背景参见 [OpenAI App Server](https://learn.chatgpt.com/docs/app-server#api-overview)。

本轮候选增加同源、精确请求 ID 绑定的取消入口；取消请求不是已退出声明。原生子进程各用新会话/进程组，取消、超时或父进程异常后仅清理精确持有的会话组；不操作共享服务。取消与结果发布串行，发布开始后拒绝过晚取消。确定性测试使用可丢弃真实子进程验证收束，不能替代真实 Codex 会话验收。零正文模型探针也计入同一个完整源单元的 8 次/1,200 秒累计预算。

实际原生成功链路、模型身份、真实 Codex 取消及完整长篇吞吐仍待验收。修复当前 CLI 准入并完成真实原生浏览器路径后才能申请完整 T02 验收。本轮不启实际服务、生产调度、真实作品或正式导出采用。

Round23 在 60 项定向测试通过后仅增加一次零正文元数据诊断，退出码 1，未见 unknown-field 分类，具体失败子步骤仍未观测。模型探针/正文生成/真实审阅均为 0；本轮已停止全部原生启动。后续需以新的具体根因证据修复，不把它表述为凭据或权限拒绝。

## Round24 刷新与恢复修复

普通状态/版本读取只消费现有检查点与作业记录，不计算 CLI/适配器全文哈希，不读配置内容或检查登录。记录中的失败仍然阻断页面；刷新、换请求 ID、重建服务对象都不能解除失败。只读状态不是准入授权，未来受控写路径仍需重算完整指纹，并在同一 app-server 生命周期核对有效配置/账号/provider/实际模型。显式重新准入与真实原生链路尚属 T02 待验收范围。

审核保存先等待当前版本刷新结束，再显示保存完成并恢复焦点。导出按钮在首次异步版本读取前绑定事件，避免初始化期间的点击丢失。沿用既有样式、键盘与手机布局；不新增轮询器。Round23 两次完整 UI 的 5 项失败保留，不能由当前新结果抹去。

隔离 UI 现在明确预置一个 synthetic failed admission，实际测试同源请求、伪造/跨源拒绝和持久失败状态，不尝试启动 Codex 或检查账号，也不写任何正向审核身份。刷新后的截图必须等完整源范围与失败原因实际加载，不能把初始 disabled 控件当恢复成功。当前完整 UI 41 通过、4 个既有跳过、0 未运行；这是工程与合成用户流程证据，真实原生生成/独立审查仍未验证。

## 拒绝后的复审与来源显示（Round34 冷态修复候选）

复审输入绑定当前项目、源清单、manifest 和逐段候选身份，只带当前规范化决定及身份匹配的拒绝反馈。时间、请求 ID、线程、随机值及无关状态不能改变语义指纹；过期反馈不用于当前候选。仍然有效的原生审核不会自动派生另一轮输入，显式保存拒绝后才可重新审查；返回当前原生决定后，再次未变的审核继续拒绝。反馈与总体输入有明确长度上限，现有源单元次数、修订和累计时间保护不变。

本机额度来源的显示由服务端核对当前候选、成功生成作业、原生回执、输出摘要与逐段输出后投影；不会从审核者、通过标签或导入声明推定原生生成。有效投影显示“本机 Agent 额度”，回执缺失、过期或不匹配显示“来源未核验”。该标识只说明生成来源，不授予候选接受或用户最终批准。页面不返回私有线程、turn 或回执正文。

本轮只准许隔离合成回归和私有浏览器检查；不启动模型、不重试 Round33，不修改其源、候选、账本或时限。冷态工程验证与真实原生全链路采用分开，当前采用和任务验收只查唯一状态。

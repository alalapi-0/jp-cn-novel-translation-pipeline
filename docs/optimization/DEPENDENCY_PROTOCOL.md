# TM and selected dependency versions

Reader: translation-memory, configuration-context, index, Workbench review and canonical-export maintainers. Update when these dependency formats or consumers change. `governance/round_state.yaml` remains the sole task state. This protocol grants no actual corpus, PSH, model, publication or final-approval effect.

TM schema 2 stores `translation_pairs`, with `approved_pairs` reserved for current, content-bound nonhuman Agent/PSH-proxy acceptances, and `machine_pairs` for explicit unreviewed translated mode. An old `approved` string never grants acceptance. Manifest and source-run paths use the same source/target and review-dependency identity. A source run can qualify as accepted only by its explicit project ID and an exact current manifest/CAS match, including direction, normalized chapter ID, segment ID, source, selected draft and dependencies. `refined_text` cannot silently override the draft. Unsupported legacy run labels stay readable but cannot issue acceptance.

Each pair stores stable source-ref/chapter/segment identity, exact source/target hashes, dependency and acceptance provenance, qualification, and a semantic version hash. Consumer rendering and batch selection re-read the explicitly referenced source and compare the complete saved pair with its current eligible form. Changed, removed, revoked, duplicated, malformed or withdrawn pairs are withheld. `withdrawn_pair_ids` withdraws selected versions in the existing JSON asset; `withdrawn: true` withholds the asset. Neither read path rewrites audit snapshots. Derived hints are recomputed from the still-current parents; saved prompts and external summaries cannot revive stale or withdrawn text. Legacy assets can be inspected through `load_translation_asset_context`, but their unbound cached prompt is not consumable. Nonstandard output locations require an explicit repository context for freshness checks.

Serialized references can open only the selected named manifest and registered local run roots; they cannot enumerate other projects or redirect source-run reads outside those roots. Registered configuration dependencies use fixed glossary/character files. A TM dependency uses a simple local asset filename and exact pair ID. Escaped/symlinked-out paths are refused. These checks constrain the domain reader; they do not establish actual source permissions or authorization.

The existing manifest/run may carry a `dependency_versions` map of local aliases to SHA256 pins. Each segment's `dependency_keys` selects only necessary entries; the reader hydrates `dependency_versions` onto that segment. Unrelated pins do not invalidate its review. Direct per-segment pins are also supported. Strict imports reject missing, duplicate, malformed or unknown selections. Runtime reads preserve independent rows: a bad selected catalog pin, direct pin or selection receives a row-scoped unavailable identity/error and cannot silently fall back to the old identity. Review identity hashes these versions, and canonical target selection preserves them. Existing source-binding/context identities remain controlling; a source-scope change may legitimately invalidate all segments using that scope.

For actual local read-through validation, `dependency_sources` maps a selected alias to one descriptor:

- `{"kind":"glossary","entry":"Alpha"}` selects the unique `source_term` in `workspace/configs/glossary.yaml`.
- `{"kind":"character","entry":"Alpha"}` selects the unique `name` in `workspace/configs/character_profile.yaml`.
- `{"kind":"tm_pair","asset":"memory.json","pair_id":"<SHA256>"}` selects a still-current pair in the existing TM store.

Only selected aliases are resolved. Configuration entry content, including knowledge withdrawal metadata, changes its digest even when prose is unchanged. Missing, malformed, ambiguous, withdrawn, cyclic or stale dependencies receive an unavailable identity and prevent affected TM reuse. Unaffected rows stay usable. Cycle detection is transient call-local state, not a new store. PSH versions remain explicitly pinned authorized snapshots in the manifest; this reader never opens the sibling PSH store or claims actual style integration. A new pinned PSH bundle version invalidates only its consumers. Actual PSH acquisition and semantic/quality judgment remain P4 work.

The configuration Prompt cache hashes the same UTF-8 bytes it parses, keeping at most 128 file generations. Emitted entries expose selected dependency hashes; irrelevant entries and entries excluded by the output budget do not become dependencies. File size and timestamps cannot mask same-size/same-second edits. This context remains subject to the existing source/narrative scope rules; having a digest does not authorize unscoped injection.

Entity-index file reuse binds exact segment bytes plus the terms and known-fragment rules actually consulted for that file. Newly appearing source/target hits, glossary deletion, changed targets and knowledge metadata invalidate the affected file; unrelated terms leave it reusable. The existing global glossary digest remains diagnostic. Segment-index schema 3 binds review dependencies into chapter content hashes and refuses old schema caches, preserving metadata-only output.

Workbench selection and export resolve live selected dependencies, including when the saved manifest SHA has not changed. Export checks again before the existing atomic bundle commit; changed dependencies preserve the previous output. No real export is performed by this engineering round. Synthetic checks prove invalidation behavior, not translation correctness, literary improvement, actual data coverage, human approval or production adoption.

# Evidence-bearing knowledge candidates

Applies to P3 knowledge import, glossary storage, character/world records, extraction adapters and source-bound narrative context. Update this protocol when their wire format or consumption rules change. The sole current task state remains `governance/round_state.yaml`.

`knowledge_claims` is an optional list on glossary, character, relationship/address and world records, and derived assets. Legacy records without it remain readable and have unknown provenance; `locked`, old approval flags and chapter numbers confer no semantic verification. Glossary round trips preserve the extension. Existing required schema fields remain required. Private extraction output retains evidence; local abstract-library export selects the actual individually checked objects and removes knowledge_claims. A shared model asset ID cannot qualify an unchecked record. This does not perform any export or external publication during the engineering round.

Each `knowledge-claim/1` stores a stable claim ID, category, statement, assertion/inference/unknown classification, nullable confidence, producer, source evidence, textual effective interval, subject/object/predicate and speaker/slot annotations, conditional target alternatives, and withdrawal state. `semantic_truth` is always `not_verified`. Model extraction fixes producer to model and cannot inherit truth or human approval; incompatible metadata becomes an unknown candidate without fabricated evidence.

Evidence binds an immutable source catalog hash, chapter and segment IDs, exact segment hash, and a half-open Unicode-codepoint quote span. `assets.knowledge.build_knowledge_context` validates those identities and adapts only active, scoped assertions to original quotes in the existing `NarrativeContextCatalog`. It never forwards the claim statement as a fact. Inference, unknown, missing proof/scope and withdrawn records stay withheld; stale evidence refuses construction. Existing per-segment textual order, exclusive end, speaker, overlap and size limits apply. Quote equality proves location, not interpretation or in-world truth. Withdrawal changes effective context identity; cache/TM dependency integration belongs to P3.R02.

Arbitration requires explicit `source_evidence` with registered chapter, full-source revision, quote and half-open span, at most eight excerpts/2400 codepoints. Missing evidence terminates that item with `ABSTAIN` before provider or source-budget reservation. Invalid evidence refuses dispatch. Counts do not prove source meaning; a response may provide contextual alternatives or abstain. Even a single-target response is an unverified local proposal with adoption and human-final flags false. Abstention is terminal and resumes without a model repeat. Checkpoint input identity includes the evidence protocol version; old statistics-only checkpoints cannot silently resume as accepted evidence.

This is an engineering contract and synthetic acceptance surface. It does not verify actual structured material, establish literary improvement, read holdout/style material, issue human approval, or enable production adoption. P3.R01.T02 and the remaining plan tasks retain those obligations.

Counts of absent standalone categories do not prove that no inline facts exist.

Each enumerated record retains its original artifact revision, generated field pointer and content hash. Glossary, character, relationship, address, world and summary records remain withheld. A legacy chapter, locked flag, approval label, model claim or copied JSON cannot qualify provenance. TM pairs, derived hints, extracted creative patterns and metadata remain derived/unverified without consumer eligibility. The finite summary and per-record redacted census establish structural coverage and explicit downgrades only. ## Independent source evidence

`assets.source_knowledge.SourceKnowledge` builds up to eight candidates from one registered complete source, without reading legacy knowledge. It uses the existing chapter parser and immutable source context catalog. Every quotation must be unique in the original and contained in one parsed paragraph; document and segment spans/hashes are computed from the source. Names must occur literally in the quote. The current input and candidate hashes bind extraction and separate non-generating review. Duplicate IDs, stale identities, missing coverage, inexact quotations and excess evidence fail closed.

An explicit assertion can receive the provisional `agent_evidence_status=source_supported` only after a separate source review with no material issue, located proof and sufficient confidence. Inferences and other uncertainty remain uncertain; contradictions remain distinct. `semantic_truth` stays `not_verified`, and all candidates remain consumer-ineligible with human-final and production flags false. This does not calibrate a semantic evaluator or establish complete chapter knowledge coverage.

Only after both native histories end may a separately authorized sealed diagnostic compare new source/target name mappings with exact frozen glossary/character rows. Exact equality is a lexical correspondence, not proof of legacy provenance or meaning. It does not change the old rows, unknown upstream dependencies or original census denominator. Legacy names, targets, notes and mappings never enter either native prompt or reviewer-visible evidence. Finite post-review evidence contains only identities, hashes, category/status/counts and location shapes. Raw source, prompts, answers, quotes, receipts and legacy values remain sealed.

Both source-only prompts also supply `quote_paragraphs` from the existing chapter parser, alongside the complete source. Each entry has a source-bound paragraph ID and its exact parser text. The catalog hash joins the input identity; extraction and nonempty review quotations must name the matching paragraph ID. A quotation may contain line breaks within one parser paragraph but cannot concatenate entries. An uncertain review may return empty quote and paragraph ID and remains withheld. Duplicate text still requires globally unique source quotation; an arbitrary paragraph ID cannot manufacture uniqueness. The catalog allows at most 4096 entries and 1 MiB of UTF-8 JSON, refuses changed source/catalog identities, and does not relax existing quote, schema, evidence or acceptance limits. These are representation bounds, not increased production budgets. The catalog repeats selected-source text solely to make quotation boundaries explicit; runtime evidence records its actual size. Earlier failed cross-paragraph reviews remain failed and their sources remain closed.

## Located development TM fidelity review

`LegacyTranslationReview` prepares two independent, non-generating review packets for at most eight frozen TM records against one complete development source. It does not read files or invoke a model. A separately approved sealed controller must first bind every record to its original census hash, registered TM artifact, exact source revision and alignment coordinates; exclude the cumulative closed-source union and all holdout targets; and reserve every physical source operation and target exposure. A prepared packet does not grant that runtime authority.

Each record carries an immutable ID/hash, ordered non-overlapping source spans and a bounded target. The source excerpt is derived directly from those coordinates. Split source spans retain their separate document ranges; an insertion point at a discontinuous join retains both possible document boundaries. Review packets preserve the complete source context and the registered direction, including CN to JP. Neither reviewer sees the other answer. At most one consequential fidelity issue per record is requested, with exact source/target quotes and half-open Unicode-codepoint coordinates; omission and addition may use the corresponding one-sided insertion point. Duplicate/missing records, stale packets, swapped reviewer identities, incorrect quotes/coordinates and privilege fields fail closed. Each view has a combined 2,400-character evidence limit.

Only concordant issue type, severity and coordinates with both confidences at least 0.8 receive `concordant_issue`. Concordant absence of an observed issue remains only that limited observation. Disagreement, low confidence and uncertainty stay uncertain. These are provisional same-model agent assessments with limited independence, not verified semantic truth or historical provenance. Finite review projections contain only record identities, source locations, enums, confidence and issue locations, with consumer eligibility, human approval and adoption false. Raw targets, quotes and reasons remain sealed. No original record, canonical target or export is changed. All original denominators and the P3/P5 full-range obligations remain in force.

# Embedding Memory Design

## 1. 为什么翻译项目需要 Embedding

长篇轻小说翻译过程中经常会遇到以下问题：

- **人名不统一**：同一角色在不同章节出现不同译名或称呼。
- **称呼不统一**：如 "王女"、"公主"、"阿蕾克西亚" 等互相混用。
- **术语前后不一致**：技能、组织、地点等专有名词在不同段落出现多种译法。
- **角色语气漂移**：角色的说话风格在后续章节逐渐偏离前期设定。
- **前文翻译风格遗忘**：在后续章节中，模型可能忘记前文使用的特定表达或格式。
- **相同概念被翻成多个版本**：如 "恢复魔法"、"治愈咒语" 等。

Embedding 可以帮助我们 **快速召回** 这些上下文信息，提供给模型作为 **检索增强** 的依据，从而提升译文的一致性与质量。

## 2. 哪些内容进入记忆库

| 内容类别 | 说明 |
|----------|------|
| `glossary.md` | 术语表，包含原文、中文译名、日文译名等字段。 |
| `character_names.md` | 人物名表，包含称呼、敬称、说话风格等信息。 |
| `style_guide.md` | 翻译风格与排版规范。 |
| `translation_rules.md` | 质量要求、审校规则。 |
| `novel_overview.md` | 整体小说设定、背景、世界观概览。 |
| 已审核译文（`output_cn/review/`） | 人工审校通过的章节或段落原文/译文对。 |
| 双语对照（`output_cn/bilingual/`） | 原文段落 ↔ 译文段落对，用于检索相似段落。 |
| 人工润色结果（`output_cn/experiments/polished_*.md`） | 已经经过润色的草稿，可作为高质量样本。 |
| 一致性检查报告（`output_cn/review/consistency_review.md`） | 检测到的不一致用例。 |
| 不确定术语记录（`notes/uncertain_terms.md`） | 模型不确定的术语，待人工确认后会进入术语库。 |

## 3. 哪些内容 **不** 进入记忆库

- `.env`、API 密钥、Token 等敏感信息。
- `logs/` 中的临时日志文件（除非明确标记为有价值的审计记录）。
- `node_modules/`、`__pycache__/`、`*.pyc` 等编译缓存。
- 大型中间文件（如完整的章节 PDF、未压缩的原始数据），除非明确标记为 `deprecated` 并需要检索。
- 未确认的草稿（除非标记为 `experimental`），以免污染检索结果。

## 4. 切块规则

### 术语类
- 按每条术语切块，一个块对应 `glossary.md` 中的单条记录。

### 人物类
- 按每个角色切块，一个块对应 `character_names.md` 中的单条记录。

### 章节译文
- 按章节划分，每章进一步按 **段落**（或 `\n\n` 分割的块）切块。

### 双语对照
- 按 **原文段落 ↔ 译文段落** 对切块，形成 `source -> translation` 关联。

### 风格指南
- 按每条规则切块，如「统一称呼」或「标点规范」等。

## 5. Metadata 设计

每个向量块必须附带以下元数据（JSON）字段：

```json
{
  "chunk_id": "string",            // 唯一 ID
  "source_file": "path",           // e.g. "notes/glossary.md"
  "source_type": "glossary|character|paragraph|bilingual|style|rule",
  "language_direction": "jp2cn|cn2jp|both",
  "chapter_no": "001" ,
  "section": "paragraph_03",
  "term": "勇者",
  "character": "阿蕾克西亚",
  "is_canon": true,
  "is_reviewed": true,
  "is_deprecated": false,
  "version": "v1",
  "tags": ["term", "chapter_001"],
  "summary": "简要描述块内容"
}
```

## 6. 检索场景

| 场景 | 说明 |
|------|------|
| **翻译前术语召回** | 初译模型在生成草稿前检索 `glossary.md`，确保使用统一译名。 |
| **润色前风格召回** | 润色模型在 Prompt 中加入相关风格指南块，以保持整体文风。 |
| **人物台词称呼召回** | 检索人物名表，确保同一角色在整部作品中称呼一致。 |
| **章节前后文召回** | 在第 N 章节润色时，检索前后章节的已审核译文段落，提供上下文参考。 |
| **相似句式召回** | 检索相似表达的段落，避免重复或冲突的译法。 |
| **一致性检查召回** | 检索已发现的不一致案例，帮助审校快速定位问题。 |
| **中译日反向术语召回** | 中译日时，根据中文术语检索对应日文表达，结合敬称与文体生成自然日文。 |

## 7. 后续实现阶段

| 阶段 | 内容 |
|------|------|
| **M0** | 仅文档规划：完成本设计文档。 |
| **M1** | 术语库结构化：实现 `glossary.md`、`character_names.md` 的统一 JSON 导出。 |
| **M2** | 切块规则实现：编写脚本将上述文件切块并生成向量（占位实现）。 |
| **M3** | Embedding 小样本索引：使用示例模型对少量块生成向量，生成索引文件。 |
| **M4** | 检索 CLI：实现 `scripts/search_translation_memory.py`，支持关键词检索。 |
| **M5** | 润色 Prompt 接入检索结果：在 refine pipeline（`src/`）中加入检索返回的上下文块。 |
| **M6** | 审核报告展示召回依据：在 `output_cn/review/polish_validation.md` 中列出检索引用的块 ID 与摘要。 |

**备注**：所有实现均保持 **dry‑run** 模式，真实向量生成与持久化仅在后续阶段通过显式用户授权后执行。
